请把 DeepSeek Remote Bridge 合并进现有服务器，并实现左上角 LOGO 的双桥切换。

先读交接文档（仓库里也有）：
D:\Deepseekwork\projects\deepseek-remote-bridge\docs\handoff.md
https://github.com/dizzynote-cell/deepseek-remote-bridge/blob/main/docs/handoff.md

关键约束：
1. DSH 桥跑在用户的 Windows 电脑上（127.0.0.1:8766），服务器只做入口和反代，通过隧道把 /dsh/ 转过去。
2. 不要在服务器上运行 DSH 运行时，不要把 DSH 的 runtime 或模型凭据搬到云端，不要改 DSH 安装目录。
3. DSH 侧设 DSH_BRIDGE_BASE_PATH=/dsh/、DSH_BRIDGE_SIBLING_URL=https://<入口页域名>/，然后重启桥。
4. 入口页左上角 LOGO 菜单加 DeepSeek Harness → /dsh/，Codex → /；可读 /dsh/api/bridge-info 的 logoMenu.targets。
5. 保存"最后使用的 provider"和各自上次会话；切换到不可达的一侧只显示离线，不重启任何进程。
6. 鉴权必须在服务器侧做（Basic Auth / 票据 / 飞书 OAuth）；DSH 侧没有登录，也不信任 X-Provider。
7. /dsh 前缀必须与 / 完全隔离：/api/*、下载、附件、sw.js 都不能串到 DSH，反之亦然。

验收：按 handoff.md §6 的 8 条逐条跑（前缀隔离、双向切换、并行任务、越权访问、余额显示、缓存/附件/停止脚本隔离、飞书单入口、回退方案），并给出部署步骤与回退办法。
