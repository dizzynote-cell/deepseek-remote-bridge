# 可选服务器入口

桥仍在 Windows 主力电脑执行，默认仅监听回环。服务器需要提供受认证的转发入口；只加一条公开反代不能代替登录。

可与 Codex Remote Bridge 的 `/dsh/` 网关配合：在自己的私有配置中填写 `DSH_BRIDGE_RELAY_URL`（HTTPS `/api/device/dsh-relay`）、`DSH_BRIDGE_RELAY_TOKEN_FILE`（与服务器一致的独立令牌文件）和 `DSH_BRIDGE_BASE_PATH=/dsh/`。不要复用模型、OAuth 或 Codex 同步令牌。

主机主动领取转发请求并回传响应，无须开放主机端口。只允许转发到自己的回环 DSH 服务；请求不会因网络超时自动重新执行，诊断接口也不能提交模型任务。健康接口的 relay 字段说明是否启用了通道、是否已连接及错误类别，不暴露令牌。

同域部署保留 `/dsh/` 前缀，不采用旧示例中的“剥前缀并配置 `/`”方式。API、静态资源、音频、上传和下载都必须经过入口验证；未登录的请求不得到达本机。

LOGO 菜单可以切换另一侧，文字和待发附件按后端、会话分别保存在浏览器本地；切换不迁移或取消真实任务。主机离线时可查看服务器已有快照，并明确显示过期状态；实时写操作不可用，不自动改发到 Codex。

配置变更后在活动任务结束时重启本桥即可。停用时移除自己的转发配置并重启本桥，不修改全局 Harness profile、其他项目服务或现有会话数据。

## 快照加速

服务器部署 DSH 的 `web/` 到 Codex 云端桥的 `dsh-web/`，并安装 `dsh_gateway.py`、`dsh_snapshots.py` 及共享的历史存储模块。本机主动同步目录、余额、设置和按需历史；服务器使用独立的 `dsh-history.db` 保存快照。实时写操作继续使用原转发通道，超时不自动重发。[完整说明](dsh-cloud-snapshots.md)。
